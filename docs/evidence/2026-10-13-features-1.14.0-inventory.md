# 1.14.0 正式版新功能盘点（逐类归档）

> 盘点日期：2026-10-13　|　依据：`docs/upstream-changelog.md` 的 `#### 1.14.0` 段（**只取正式段**，不含 `-alpha/-beta/-rc`）　|　工具版本：sing-box 1.14.3（锁定版）

## 为什么要做这次盘点

上游每个正式版都会引入新功能。本仓库的新功能覆盖比对（`audit_new_features()` 的第 5 步）
只比对 `>= policy.coverage_floor` 的**正式版段**，而 `coverage_floor` 起初不存在
—— 覆盖窗口的起点一度被隐式地当成「当前锁定版」，于是**锁定版之前的每一个正式版都掉进了窗口外**：
1.14.0 引入的 49 条新功能从来没有被逐条盘过，而门禁一片绿。

本次盘点把 1.14.0 的 49 条逐类归档，并把结论钉在矩阵里（`policy.inventories`），
从此 1.14.0 不再是「无人盘点的历史」。

## 盘点口径

* 数据源：`docs/upstream-changelog.md` 的 `#### 1.14.0` 段（该段在文件里只出现一次）。
* 严格排除 `1.14.0-alpha.*` / `-beta.*` / `-rc.*` 段。实测：不筛正式段时 1.14.0 名下会膨胀到
  102 条，其中 53 条（OpenVPN、Cloudflare Origin CA、APK 包、macOS backport…）
  **根本不在 1.14.0 正式版发布说明里**。
* 分类判据：**「该功能有没有落在本仓库三份 profile（Android / iOS / Desktop，均为 tun 型）的配置面上」。**

## A 类 —— 已采纳并写进配置（2 条，逐条登记）

| 编号 | 功能 | 本仓库决策 | 落地位置 |
| --- | --- | --- | --- |
| 15 | Add optimistic DNS cache | 启用 | `dns.optimistic: true` |
| 20 | Add new UDP NAT options | 部分启用（只定上限） | `inbounds[type=tun].udp_nat_max: 4096` |

* **`new_dns_optimistic_cache`** —— 缓存条目过期但仍在窗口（默认 `3d`）内时先返回旧值、
  后台刷新。对移动端「切网后第一次请求要等 DNS」的体感有直接改善。
  官方文档明确它与 `disable_cache` / `disable_expire` 冲突；本仓库两份都没用，无冲突。
* **`new_udp_nat_max`** —— 官方默认行为是「未设或为 0 ⇒ iOS 用 4096，其他平台按内存总量
  在 4096–16384 之间取，探测不到内存时用 16384」。也就是说**不写就没有上限**。
  本仓库显式写 4096，是给非 iOS 平台加一道内存上限，直接对应历史上那次
  「Android 端内存占用瞬间冲到 1GB」的事故方向。
  同段引入的 `udp_mapping` / `udp_filtering` 保持官方默认（`endpoint_independent`），不写。

## B 类 —— 判据在配置面上，但本仓库决定不启用（约 18 条）

这些功能的字段本仓库都没有，`expect: absent` 的断言由 `audit_matrix()` 逐份配置检查。

| 编号 | 功能 | 不启用的理由（摘要） |
| --- | --- | --- |
| 1 | `evaluate` DNS rule action / Response Match Fields | 需要按响应内容二次分流；本仓库 DNS 分流只用域名规则，够用 |
| 5 | `ip_version` / `query_type` 对内部 DNS 解析生效 | **已在用**（`resolve(ipv4_only)` + `reject(ip_version:6)` 成立的前提），无需额外字段 |
| 6 | Correct undefined rule-set matching semantics | 修正类，无字段；本仓库规则集顺序已按新语义对齐 |
| 7 | mDNS DNS server / `preferred_by` / search domain rule items | 家庭局域网场景才需要；移动端 profile 不引入 |
| 8 | `source_mac_address` / `source_hostname` rule items | 需要 MAC 与主机名，Android/iOS 图形客户端拿不到 |
| 12 | Allow customizing TUN DNS mode / 默认劫持 interface DNS | Android 上 `dns_mode` 与系统 VPN 的 DNS 交互复杂，风险大于收益 |
| 16 | `sniff` support for pre-match | **已在用**（`route.rules[0]` 的 `{"action":"sniff"}`） |
| 17 | Unify HTTP client | **已在用**（`http_clients` + 规则集的 `http_client`），1.14 引入的显式写法 |
| 18 | Unify HTTP/2 and QUIC parameters | 与本仓库节点类型无关（无 HTTP/2 型出站调参需求） |
| 19 | Add TLS spoof | 需要服务端配合，且属主动探测规避手段，不引入 |
| 22 | rule-set 多 tag / `initial_path` | 本仓库每条规则集一个 tag、无初始路径需求 |
| 23 | `package_name_regex` | 现有 `package_name` 已覆盖需求；regex 更难复核 |
| 24 | `query_client_subnet` / `query_dnssec` / `remove_client_subnet` | EDNS Client Subnet 会向 DNS 上游暴露网段，移动端不做 |
| 25 | `include_mac_address` / `exclude_mac_address` | 官方限制：仅 Linux + `auto_route` + `auto_redirect`，三平台都用不上 |
| 27 | `handshake_timeout`（TLS） | 默认 15s 已合适，无实测依据说明需要改 |
| 28 | Tailscale `listen_port` / `accept_search_domain` | 本仓库不用 Tailscale |
| 29 | Preserve comments between formatting | 工具行为，无配置字段 |
| 37 | sing-box for Desktop（Windows/Linux） | 客户端形态，与配置文件无关 |

## C 类 —— 判据不在配置面上（约 29 条，按类归档，不逐条登记）

这些是协议实现、发布工程、依赖升级、客户端 UI 一类的东西 ——
**没有任何字段能让它们落到三份 tun 型 profile 里**，因此「启用/不启用」这个问题本身不成立。
逐条登记只会产出 29 条 `adopt: no` + 一句空理由的空壳条目，反而稀释真正的决策。

| 子类 | 条目编号 | 说明 |
| --- | --- | --- |
| 新增协议 / 出站 | 2, 3, 4, 9, 26, 34 | OpenVPN、OpenConnect、Snell、USB/IP、Hysteria Realm + Hy2 NAT 穿透、Tailscale SSH + Taildrop、SSH 出站算法选项 |
| 平台专属能力 | 11, 33, 35 | L3 forwarding + bridge 出站、network namespace、cloudflared 入站 —— 均面向软路由/服务端 |
| 服务端 / 证书体系 | 21, 22 | API service + Dashboard + remote control、ACME → certificate provider 重构、Cloudflare Origin CA |
| TLS/HTTP 引擎 | 23 | Windows / Apple TLS engine、Apple HTTP engine —— 引擎由客户端平台决定，不由配置声明 |
| 发布与工程 | 1, 38, 40, 41, 43 | iOS/tvOS 回 App Store、iOS 越狱包、`api` command、beta/testing/oldstable 轨道、`sing-box for Desktop` 之外的发行改进 |

## 结论与后续

* 矩阵登记：`new_dns_optimistic_cache`、`new_udp_nat_max` 两条 `kind=new`，`since: "1.14.0"`，
  均 `adopt: "yes"` / `expect: "present"`，`inventory` 指向本文档。
* 覆盖窗口：`policy.coverage_floor` 从此钉住，`policy.inventories` 记录「1.14.0 已盘点」。
* 下次升级（1.15.0 正式版发布）时，窗口 = `(1.14.0, 1.15.0]` 的正式版段，
  只有 1.15.0 那一版的新功能需要比对 —— 1.14.0 的 49 条永远不再重复盘点。
